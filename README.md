# Учебный портал: курсы, заявки и библиотека

Учебное веб-приложение на Django для кафедры. Студенты подают заявки на запись на курсы и заявки на выдачу учебников, методист рассматривает заявки, зачисляет студентов, выдаёт учебники и принимает их возврат. Данные хранятся в базе данных, интерфейс работает с ними через REST API без перезагрузки страницы.

Проект выполнен в рамках дисциплины «Структура программного обеспечения и базы данных» (ПЗ №5–8, СРС №7–8).

Рабочая версия: https://spoibd-pz5.onrender.com (бесплатный тариф Render: после 15 минут простоя первое открытие занимает около минуты).

## Возможности

- Вход по логину и паролю, две роли: студент и методист (группа «Методист» в Django).
- Справочники факультетов, курсов и учебных групп; изменять их может только методист.
- Дашборды по курсам и студентам с графиками.
- Страница «Заявки» (`/api-dashboard/`): студент подаёт заявку на курс, методист зачисляет или отклоняет её с учётом числа мест.
- Страница «Библиотека» (`/library/`): студент создаёт заявку на учебник, методист выдаёт учебник и принимает возврат. Число свободных экземпляров меняется автоматически, у каждой заявки есть история событий.
- Фильтры заявок на учебники по статусу и курсу выполняются на сервере.

Ограничения:

- студент видит и меняет только свои заявки, чужие для него не существуют (ответ 404);
- статус заявки на учебник меняется только действиями «выдать», «принять возврат», «отменить» и только по разрешённым переходам;
- регистрация пользователей через сайт не предусмотрена, учётные записи создаются в административной панели.

## Технологии

| Компонент | Назначение |
|---|---|
| Python 3.12 или новее | язык серверной части (проверено на 3.13) |
| Django 6.1 | веб-фреймворк, ORM, шаблоны, административная панель |
| Django REST Framework 3.18 | REST API для заявок, курсов и учебников |
| Tabler 1.x, JavaScript (fetch) | оформление и динамические страницы, файлы лежат в `static/vendor` |
| Chart.js 4 | графики на дашбордах |
| SQLite | база данных при локальной разработке |
| PostgreSQL + psycopg 3 | база данных на Render |
| dj-database-url | выбор базы данных по переменной `DATABASE_URL` |
| python-dotenv | чтение настроек из файла `.env` при локальном запуске |
| Gunicorn | сервер приложений на Render |
| WhiteNoise | раздача собранных статических файлов при `DEBUG=False` |

## Структура проекта

```
SPOiBD_PZ5/
├── config/                 пакет настроек проекта
│   ├── settings.py         настройки; секреты и режим читаются из переменных окружения
│   ├── urls.py             корневые маршруты: /admin/, /accounts/, /healthz/, маршруты приложения
│   └── wsgi.py             точка входа для Gunicorn
├── accounts/               основное приложение
│   ├── models.py           модели: факультеты, курсы, группы, профили, заявки, учебники, история
│   ├── serializers.py      сериализаторы REST API и проверка данных
│   ├── services.py         бизнес-логика выдачи учебников (переходы статусов, транзакции)
│   ├── views.py            страницы сайта и наборы представлений API
│   ├── urls.py             маршруты страниц и REST API (/api/...)
│   ├── admin.py            регистрация моделей в административной панели
│   ├── tests.py            автоматические тесты процесса выдачи учебников
│   ├── management/commands/
│   │   ├── seed_demo.py    тестовые факультеты, курсы, группы и студенты
│   │   └── seed_library.py группа «Методист» и учебники для курсов
│   ├── migrations/         миграции базы данных
│   ├── templates/accounts/ страницы «Заявки» и «Библиотека»
│   └── static/accounts/    api.js (общие функции запросов), app.js, library.js
├── templates/              общие шаблоны: base.html, списки, формы, дашборды, вход
├── static/                 стили проекта и библиотеки Tabler, Chart.js (static/vendor)
├── docs/                   подробная документация
├── build.sh                сценарий сборки на Render
├── requirements.txt        зависимости Python с версиями
├── .env.example            образец переменных окружения без секретов
└── manage.py               утилита управления Django
```

Папки `venv/`, `staticfiles/`, файлы `db.sqlite3` и `.env` создаются при запуске и в репозиторий не попадают (см. `.gitignore`). Файлы `package.json` и `node_modules/` использовались, чтобы скачать Tabler и Chart.js; для запуска проекта они не нужны, нужные файлы уже скопированы в `static/vendor`.

## Быстрый старт (Windows, PowerShell)

Нужны Python 3.12+ и Git. Проверка версий: `python --version`, `git --version`.

```powershell
git clone https://github.com/reallyspring/SPOiBD_PZ5.git
cd SPOiBD_PZ5
python -m venv venv
venv\Scripts\activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
Copy-Item .env.example .env
python manage.py migrate
python manage.py seed_demo
python manage.py seed_library
python manage.py createsuperuser
python manage.py runserver
```

Для Linux и macOS отличаются две команды: `source venv/bin/activate` вместо `venv\Scripts\activate` и `cp .env.example .env` вместо `Copy-Item`.

Что делает каждый шаг:

1. `python -m venv venv` и `activate` создают и включают виртуальное окружение. В начале строки терминала появится `(venv)`.
2. `pip install -r requirements.txt` устанавливает зависимости тех же версий, что на сервере.
3. `Copy-Item .env.example .env` создаёт файл настроек. Значений из образца достаточно для локального запуска. В `.env` можно заменить `DJANGO_SECRET_KEY` на свою строку.
4. `migrate` создаёт таблицы в файле `db.sqlite3`.
5. `seed_demo` заполняет базу факультетами, курсами, группами и студентами (`student1`, `student2`, …). Запускайте один раз: повторный запуск создаст копии. Пароль тестовых студентов указан в `accounts/management/commands/seed_demo.py`.
6. `seed_library` создаёт группу «Методист» и по одному учебнику (2 экземпляра) для каждого курса. Повторный запуск безопасен.
7. `createsuperuser` создаёт администратора для входа в `/admin/`.

### Учётная запись методиста

1. Откройте http://127.0.0.1:8000/admin/ и войдите под администратором.
2. Users → Add user → логин `methodist` и пароль → Save.
3. На странице пользователя в поле Groups выберите «Методист» → Save.

## Переменные окружения

| Переменная | Назначение | Пример |
|---|---|---|
| `DJANGO_SECRET_KEY` | секретный ключ для подписи сессий и CSRF-токенов; без него проект не запускается | `replace-with-a-long-random-string` |
| `DJANGO_DEBUG` | `True` — подробные ошибки для разработки, `False` — режим эксплуатации | `True` |
| `DJANGO_ALLOWED_HOSTS` | домены, для которых Django обрабатывает запросы, через запятую, без протокола | `127.0.0.1,localhost` |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | адреса с протоколом, с которых разрешены изменяющие запросы | `http://127.0.0.1:8000` |
| `DATABASE_URL` | адрес базы данных; если не задан, используется SQLite | `postgresql://USER:PASSWORD@HOST:5432/DBNAME` |

Локально переменные читаются из `.env`. На Render они задаются в разделе Environment веб-сервиса. Подробно: [docs/deployment.md](docs/deployment.md).

## Проверка работы

1. **Сервер.** http://127.0.0.1:8000/healthz/ отвечает `{"status": "ok"}`.
2. **Интерфейс.** Войдите студентом, откройте «Библиотека»: страница оформлена (тёмная тема Tabler), в списке учебников есть свободные экземпляры.
3. **API.** Создайте заявку на учебник. В DevTools → Network виден `POST /api/loans/` с ответом 201, затем `GET /api/loans/` с ответом 200.
4. **База данных.** Остановите сервер (Ctrl+C), запустите снова и обновите страницу: заявка на месте. Та же запись видна в `/admin/accounts/bookloan/`.
5. **Бизнес-правила.** Войдите методистом, нажмите «Выдать»: статус станет «Выдан», свободных экземпляров станет меньше, в истории появится событие.
6. **Тесты.** `python manage.py test accounts` → `Ran 12 tests ... OK`. Строки `Bad Request` и `Forbidden` в выводе — это журнал ожидаемых ошибок из тестов, а не сбой.
